Multica 使用邮箱和密码登录。注册时不验证邮箱归属；已有用户使用自己设置的密码登录，注册限制只决定能否创建新账号。

## 邮箱和密码

在登录页选择**创建账号**，输入邮箱并设置至少 8 个字符的密码。注册成功后，使用同一邮箱和密码登录。

<Callout type="warning">
注册不验证邮箱归属。需要将访问限制在已知人员范围时，请使用 `ALLOW_SIGNUP=false` 并配置白名单。
</Callout>

## 用于邀请的邮件发送

密码登录不需要邮件服务。需要发送工作区邀请链接，或在旧账号迁移窗口中发送验证码时，请配置 Resend 或 SMTP；两者同时配置时，`SMTP_HOST` 优先。

### 使用 Resend

1. 在 [Resend](https://resend.com/) 验证发信域名并创建 API key。
2. 设置：

   ```dotenv
   RESEND_API_KEY=re_xxxxxxxxxxxxxxxx
   RESEND_FROM_EMAIL=noreply@example.com
   ```

3. 重启 API 服务。

`RESEND_FROM_EMAIL` 必须属于已经在 Resend 验证的域名。

### 使用 SMTP

最少需要设置主机和发件地址：

```dotenv
SMTP_HOST=smtp.example.com
SMTP_PORT=587
SMTP_USERNAME=multica
SMTP_PASSWORD=<password>
SMTP_FROM_EMAIL=noreply@example.com
```

| 场景 | 配置 |
|---|---|
| 内网匿名 relay | `SMTP_PORT=25`，用户名和密码留空 |
| STARTTLS | `SMTP_PORT=587`；服务器支持时默认升级到 TLS |
| 隐式 TLS | `SMTP_PORT=465`，或显式设置 `SMTP_TLS=implicit` |

没有设置 `SMTP_FROM_EMAIL` 时，会回退到 `RESEND_FROM_EMAIL`。私有 CA 或自签证书需要加入容器信任库；`SMTP_TLS_INSECURE=true` 会跳过证书校验，只应在可信内网中临时使用。

没有邮件服务时，服务器仍可启动，但会拒绝新工作区邀请和旧账号验证码请求。邀请链接和验证码都是能力凭据，绝不会写入日志。

升级到此版本会使能力令牌引入前创建的所有待处理邀请过期；仍需有效的邀请请重新发出。

## 注册范围控制

三个变量共同决定是否可以创建新账号：

| 变量 | 作用 |
|---|---|
| `ALLOWED_EMAILS` | 允许注册的完整邮箱，多个值用逗号分隔 |
| `ALLOWED_EMAIL_DOMAINS` | 允许注册的邮箱域名，多个值用逗号分隔 |
| `ALLOW_SIGNUP` | 未配置任何白名单时是否允许注册；默认 `true` |

判断顺序如下：

1. 邮箱命中 `ALLOWED_EMAILS`，允许。
2. 或域名命中 `ALLOWED_EMAIL_DOMAINS`，允许。
3. 未命中时，若 `ALLOW_SIGNUP=false`，拒绝。
4. `ALLOW_SIGNUP=true` 但设置了任意白名单且未命中，仍然拒绝。
5. 没有白名单且 `ALLOW_SIGNUP=true`，允许。

常见配置：

```dotenv
# 只允许公司域名
ALLOW_SIGNUP=false
ALLOWED_EMAIL_DOMAINS=company.com

# 再放行一位外部协作者
ALLOWED_EMAILS=partner@example.net
```

<Callout type="info">
两个白名单在 `ALLOW_SIGNUP=false` 时也可以作为明确的例外名单。已预先创建但尚未设置密码的账号，不能通过公开注册设置初始密码。
</Callout>

## 旧账号迁移

对安装版客户端和密码登录前创建的账号，可在受控兼容窗口中设置 `AUTH_LEGACY_AUTH_ENABLED=true`。旧的邮箱验证码和 Google 接口只会认证尚未设置密码的已有账号，绝不会创建账号或修改密码。

旧账号使用邮件验证码登录后，网页会要求其设置密码。完成迁移前请保持邮件投递可用；如果旧版安装客户端使用过 Google OAuth，也请保留原有的 `GOOGLE_CLIENT_ID`、`GOOGLE_CLIENT_SECRET` 和已注册的 `GOOGLE_REDIRECT_URI`。根据旧认证路由的服务端遥测和客户端版本采用情况决定何时设为 `false` 并重启 API；关闭后旧路由会返回 `410 Gone`，让过期客户端获得升级信号。

## 登录有效期

浏览器登录默认保持 30 天。可以用 `AUTH_TOKEN_TTL` 调整，支持 Go duration 或正整数秒数：

```dotenv
AUTH_TOKEN_TTL=720h
```

修改后需要重启 API 服务。该值只影响之后签发的登录 cookie 和 JWT，不会延长已经签发的令牌。
