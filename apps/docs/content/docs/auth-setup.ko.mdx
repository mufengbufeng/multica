Multica는 이메일과 비밀번호로 로그인합니다. 가입 시 이메일 소유 여부를 확인하지 않습니다. 기존 사용자는 설정한 비밀번호로 로그인하며 가입 제한은 새 계정을 만들 수 있는지만 결정합니다.

## 이메일과 비밀번호

로그인 화면에서 **계정 만들기**를 선택하고 이메일과 8자 이상인 비밀번호를 입력합니다. 가입 후에는 같은 이메일과 비밀번호로 로그인합니다.

<Callout type="warning">
가입 시 이메일 소유 여부를 확인하지 않습니다. 알려진 사용자 그룹으로만 접근을 제한해야 한다면 `ALLOW_SIGNUP=false`와 allowlist를 함께 사용하세요.
</Callout>

## 초대 이메일 발송

비밀번호 로그인에는 이메일 전송이 필요하지 않습니다. 워크스페이스 초대 링크나 이전 계정 마이그레이션 중의 인증 코드를 보내려면 Resend 또는 SMTP를 설정하세요. 둘 다 설정하면 `SMTP_HOST`가 우선합니다.

### Resend 사용

1. [Resend](https://resend.com/)에서 발신 도메인을 인증하고 API key를 만듭니다.
2. 다음을 설정합니다.

   ```dotenv
   RESEND_API_KEY=re_xxxxxxxxxxxxxxxx
   RESEND_FROM_EMAIL=noreply@example.com
   ```

3. API 서비스를 다시 시작합니다.

`RESEND_FROM_EMAIL`은 Resend에서 인증한 도메인에 속해야 합니다.

### SMTP 사용

최소한 host와 발신 주소를 설정해야 합니다.

```dotenv
SMTP_HOST=smtp.example.com
SMTP_PORT=587
SMTP_USERNAME=multica
SMTP_PASSWORD=<password>
SMTP_FROM_EMAIL=noreply@example.com
```

| 환경 | 설정 |
|---|---|
| 내부 네트워크 익명 relay | `SMTP_PORT=25`, 사용자 이름과 비밀번호는 비워 둠 |
| STARTTLS | `SMTP_PORT=587`, 서버가 지원하면 기본적으로 TLS로 업그레이드 |
| 암시적 TLS | `SMTP_PORT=465` 또는 `SMTP_TLS=implicit` 명시 |

`SMTP_FROM_EMAIL`을 설정하지 않으면 `RESEND_FROM_EMAIL`을 사용합니다. 사설 CA나 자체 서명 인증서는 컨테이너 신뢰 저장소에 추가해야 합니다. `SMTP_TLS_INSECURE=true`는 인증서 검증을 건너뛰므로 신뢰할 수 있는 내부 네트워크에서만 임시로 사용하세요.

이메일 서비스가 없어도 서버는 시작하지만 새 워크스페이스 초대와 이전 계정 인증 코드 요청은 거부합니다. 초대 링크와 인증 코드는 capability credential이므로 로그에 남기지 않습니다.

이 버전으로 업그레이드하면 capability token 도입 전에 생성된 모든 pending 초대가 만료됩니다. 계속 유효해야 하는 초대는 다시 보내세요.

## 가입 제한

세 가지 변수가 새 계정을 만들 수 있는지 결정합니다.

| 변수 | 효과 |
|---|---|
| `ALLOWED_EMAILS` | 가입을 허용할 전체 이메일 주소. 여러 값은 쉼표로 구분 |
| `ALLOWED_EMAIL_DOMAINS` | 가입을 허용할 이메일 도메인. 여러 값은 쉼표로 구분 |
| `ALLOW_SIGNUP` | allowlist가 없을 때 가입을 허용할지 여부. 기본값은 `true` |

평가 순서는 다음과 같습니다.

1. 이메일이 `ALLOWED_EMAILS`와 일치하면 허용합니다.
2. 또는 도메인이 `ALLOWED_EMAIL_DOMAINS`와 일치하면 허용합니다.
3. 일치하지 않고 `ALLOW_SIGNUP=false`이면 거부합니다.
4. `ALLOW_SIGNUP=true`여도 allowlist가 하나라도 설정되어 있고 일치하지 않으면 거부합니다.
5. allowlist가 없고 `ALLOW_SIGNUP=true`이면 허용합니다.

일반적인 설정:

```dotenv
# 회사 도메인만 허용
ALLOW_SIGNUP=false
ALLOWED_EMAIL_DOMAINS=company.com

# 외부 협업자 한 명도 허용
ALLOWED_EMAILS=partner@example.net
```

<Callout type="info">
두 allowlist는 `ALLOW_SIGNUP=false`일 때 명시적인 예외 목록으로도 동작합니다. 미리 생성되었지만 아직 비밀번호가 없는 계정은 공개 등록으로 초기 비밀번호를 설정할 수 없습니다.
</Callout>

## 이전 계정 마이그레이션

설치형 클라이언트와 비밀번호 로그인 이전에 만들어진 계정에는 제어된 호환 기간 동안 `AUTH_LEGACY_AUTH_ENABLED=true`를 사용하세요. 이전 이메일 코드와 Google 엔드포인트는 비밀번호가 없는 기존 계정만 인증하며 계정을 만들거나 비밀번호를 변경하지 않습니다.

이전 계정이 이메일 코드로 로그인하면 웹 로그인 화면에서 비밀번호를 설정하게 됩니다. 마이그레이션이 끝날 때까지 이메일 전송을 유지하세요. 이전 설치형 클라이언트가 Google OAuth를 사용했다면 기존 `GOOGLE_CLIENT_ID`, `GOOGLE_CLIENT_SECRET`, 등록된 `GOOGLE_REDIRECT_URI`도 유지해야 합니다. 서버의 이전 인증 라우트 telemetry와 클라이언트 배포 현황을 확인한 뒤 `false`로 설정하고 API를 재시작하세요. 비활성화된 이전 라우트는 오래된 클라이언트에 `404` 대신 `410 Gone`을 반환합니다.

## 세션 유효 기간

브라우저 로그인은 기본적으로 30일 동안 유지됩니다. `AUTH_TOKEN_TTL`로 조정할 수 있으며 Go duration 또는 양의 정수 초를 받습니다.

```dotenv
AUTH_TOKEN_TTL=720h
```

변경 후 API 서비스를 다시 시작하세요. 이 값은 이후에 발급하는 로그인 cookie와 JWT에만 적용되며 이미 발급된 토큰의 기간을 늘리지는 않습니다.
