Multica はメールアドレスとパスワードでログインします。登録時にメールアドレスの所有確認は行いません。既存ユーザーは設定したパスワードでログインし、サインアップ制限は新しいアカウントを作成できるかだけを決めます。

## メールアドレスとパスワード

ログイン画面で**アカウントを作成**を選び、メールアドレスと 8 文字以上のパスワードを入力します。登録後は同じメールアドレスとパスワードでログインします。

<Callout type="warning">
登録ではメールアドレスの所有確認を行いません。既知のグループだけにアクセスを限定する場合は、`ALLOW_SIGNUP=false` と allowlist を併用してください。
</Callout>

## 招待メールの配信

パスワードログインにメール配信は不要です。ワークスペース招待リンクや、旧アカウント移行期間中の認証コードを送る場合は Resend または SMTP を設定します。両方を設定した場合は `SMTP_HOST` が優先されます。

### Resend を使う

1. [Resend](https://resend.com/) で送信ドメインを検証し、API key を作成します。
2. 次を設定します:

   ```dotenv
   RESEND_API_KEY=re_xxxxxxxxxxxxxxxx
   RESEND_FROM_EMAIL=noreply@example.com
   ```

3. API サービスを再起動します。

`RESEND_FROM_EMAIL` は、Resend で検証済みのドメインに属している必要があります。

### SMTP を使う

最低限、ホストと送信元アドレスを設定します:

```dotenv
SMTP_HOST=smtp.example.com
SMTP_PORT=587
SMTP_USERNAME=multica
SMTP_PASSWORD=<password>
SMTP_FROM_EMAIL=noreply@example.com
```

| シナリオ | 設定 |
|---|---|
| 内部の匿名 relay | `SMTP_PORT=25`。ユーザー名とパスワードは空のまま |
| STARTTLS | `SMTP_PORT=587`。サーバーが対応していればデフォルトで TLS にアップグレード |
| 暗黙的 TLS | `SMTP_PORT=465`、または `SMTP_TLS=implicit` を明示的に設定 |

`SMTP_FROM_EMAIL` が未設定の場合は `RESEND_FROM_EMAIL` にフォールバックします。プライベート CA や自己署名証明書を使う場合は CA をコンテナの信頼ストアに追加してください。`SMTP_TLS_INSECURE=true` は証明書検証をスキップするため、信頼できる内部ネットワークで一時的に使う場合に限ってください。

メールサービスがなくてもサーバーは起動しますが、新しいワークスペース招待と旧アカウントの認証コード要求は拒否されます。招待リンクと認証コードは能力資格情報のため、ログには出力されません。

このリリースへのアップグレードでは、能力トークン導入前に作成された保留中の招待がすべて失効します。引き続き有効にしたい招待は再送してください。

## サインアップ制限

3 つの変数が組み合わさって、新しいアカウントを作成できるかどうかを決めます:

| 変数 | 効果 |
|---|---|
| `ALLOWED_EMAILS` | 登録を許可する完全なメールアドレス。複数はカンマ区切り |
| `ALLOWED_EMAIL_DOMAINS` | 登録を許可するメールドメイン。複数はカンマ区切り |
| `ALLOW_SIGNUP` | allowlist が一つも設定されていない場合に新規登録を許可するか。デフォルトは `true` |

判定順序は次のとおりです:

1. メールアドレスが `ALLOWED_EMAILS` に一致すれば許可。
2. またはドメインが `ALLOWED_EMAIL_DOMAINS` に一致すれば許可。
3. どちらにも一致せず、`ALLOW_SIGNUP=false` なら拒否。
4. `ALLOW_SIGNUP=true` でも、いずれかの allowlist が設定されていて一致しなければ、やはり拒否。
5. allowlist が一つも設定されておらず、`ALLOW_SIGNUP=true` なら許可。

よくある設定:

```dotenv
# 会社ドメインのみ許可
ALLOW_SIGNUP=false
ALLOWED_EMAIL_DOMAINS=company.com

# 外部コラボレーターを 1 人追加で許可
ALLOWED_EMAILS=partner@example.net
```

<Callout type="info">
2 つの allowlist は、`ALLOW_SIGNUP=false` のときには明示的な例外リストとしても機能します。事前に作成され、まだパスワードのないアカウントは、公開登録で初期パスワードを設定できません。
</Callout>

## 旧アカウントの移行

インストール済みクライアントとパスワードログイン以前に作成されたアカウントでは、制御された互換期間中に `AUTH_LEGACY_AUTH_ENABLED=true` を使います。旧メールコードと Google エンドポイントは、パスワードを設定していない既存アカウントだけを認証し、アカウント作成やパスワード変更は行いません。

旧アカウントがメールコードでログインすると、Web のログイン画面でパスワード設定を求められます。移行が終わるまでメール配信を維持してください。旧インストール済みクライアントで Google OAuth を使っていた場合は、既存の `GOOGLE_CLIENT_ID`、`GOOGLE_CLIENT_SECRET`、登録済みの `GOOGLE_REDIRECT_URI` も保持します。旧認証ルートのサーバーテレメトリーとクライアントの導入状況を確認してから `false` に設定し、API を再起動してください。無効化後の旧ルートは、古いクライアントに `404` ではなく `410 Gone` を返します。

## セッション有効期間

ブラウザのログインはデフォルトで 30 日間保持されます。`AUTH_TOKEN_TTL` で調整でき、Go duration または正の整数秒を受け付けます:

```dotenv
AUTH_TOKEN_TTL=720h
```

変更後は API サービスの再起動が必要です。この値は、それ以降に発行されるログイン cookie と JWT にのみ影響し、発行済みのトークンを延長することはありません。
